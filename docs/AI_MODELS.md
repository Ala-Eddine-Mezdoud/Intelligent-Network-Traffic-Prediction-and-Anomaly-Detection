# AI Models Reference

## GNN Inference Engine — TemporalGAT

### Architecture

`TemporalGAT` combines temporal and spatial learning:

1. **Temporal encoding** — a 2-layer bidirectional LSTM processes a sequence of 5 consecutive telemetry snapshots (40 seconds of history) per node, producing a temporal embedding
2. **Spatial aggregation** — 3 layers of Graph Attention Network (GAT) with multi-head attention aggregate information across graph neighbors using the network topology as the edge structure
3. **Dual classification heads:**
   - Node classifier: MLP on each node's spatial embedding → per-node anomaly class
   - Window classifier: mean-pooled graph embedding concatenated with mean node logits → global network state

### Input

- **Graph nodes:** 20 non-router hosts (routers are excluded; they carry relay traffic, not application traffic)
- **Node features:** 14 values per node, polled every 8 seconds (see `docs/SIMULATION.md`)
- **Sequence length:** 5 windows (configurable; minimum to start predictions)
- **Edge structure:** physical topology adjacency (static, derived from `topology.py`)

### Output classes (9)

| Class | Meaning |
|-------|---------|
| NORMAL | Healthy baseline traffic |
| CONGESTION | Link saturation / queue buildup |
| LATENCY | Abnormal propagation delay |
| PACKET_LOSS | Elevated drop rate |
| JITTER | High latency variance |
| BANDWIDTH | Rate-limited traffic |
| INFRA_FAILURE | Severe degradation (brownout) |
| DDOS | Distributed flood attack |
| SCANNING | Reconnaissance activity |

### Override rules

After the model produces a prediction, the inference engine applies deterministic overrides:

1. **Netem check** (highest priority) — reads raw `netem_delay_ms` and `netem_loss_pct` features directly from the current snapshot. If `delay > 100 ms` or `loss > 2%` on any node, the model output is replaced with the matching operational class.
2. **Active injection pin** — when an anomaly was explicitly injected via `inject_anomaly()`, the correct label is pinned for the injection duration, overriding both the model and the netem check.
3. **SCANNING suppression** — always disabled in normal simulation. The training distribution had `mean(tcp_connections) ≈ 1` per node; normal simulation runs 14 persistent flows so `tcp_connections ≈ 14` per host, causing the model to consistently misclassify as SCANNING.
4. **JITTER / BANDWIDTH suppression** — disabled in normal simulation; only valid when a jitter or bandwidth-cap injection is active.

### Confidence gates

- Window-level prediction: reported only if confidence ≥ 55%
- Node-level prediction: flagged as anomaly only if confidence ≥ 50%

### Warm-up period

The engine buffers 5 telemetry snapshots (40 seconds) before emitting its first prediction. During this period the dashboard shows the simulation as running but no GNN state is displayed.

## IDS Pipeline — Random Forest Classifier

### Model

`ids_pipeline.pkl` contains a sklearn `Pipeline` with two stages:
1. `StandardScaler` — zero-mean, unit-variance normalization of CICIDS-style flow features
2. `RandomForestClassifier` — trained on 2420 synthetic flow samples covering 15 attack classes

### Features

CICIDS-style per-flow aggregate features: duration, byte rates, packet rates, inter-arrival time statistics, packet length statistics, TCP flag counts, protocol.

### Heuristic priority cascade

Heuristic rules run before the ML model. The first matching rule determines the label; the ML model is only consulted at P9 if no heuristic matched.

See [docs/SIMULATION.md — IDS Pipeline](SIMULATION.md#ids-pipeline) for the full P1–P9 rule table.

### False positive suppression in normal simulation

The IDS snapshot runs every 90 seconds on `dc_sw` interfaces. During normal simulation with no attack injection:

- P1 is skipped because `attack_hint=None`
- P2/P3 are skipped because all iperf3 flows use ports 5200–5330 (`IPERF3_PORTS`)
- P4 is skipped for the same reason (port exclusion added in P4 rule)
- P5/P6 do not trigger because iperf3 flows use a single destination per flow
- P9 rarely fires because RandomForest trained on attack flows has low confidence on iperf3 patterns

The result is zero false-positive anomalies during clean simulation. Anomalies only appear after explicit attack injection.

## Traffic Forecast Model

The traffic forecast displayed in the dashboard is generated by the GNN inference engine, not by a separate ML model.

**Algorithm:** EWMA trend extrapolation

```
α = 0.35
window = last 8 historical values
ewma = exponentially-weighted moving average over window
slope = (hist[-1] - hist[-5]) / 4          (last 5 values)
std_dev = sample std deviation of last 12 values

For step idx in 1..12:
    damping = 0.92^idx
    predicted = max(0, base + slope × idx × damping)
    band = std_dev × (1 + idx × 0.08)
    upper = predicted + band
    lower = max(0, predicted - band)
```

The slope is biased based on the current GNN window state:
- `DDOS` — slope biased upward (attack traffic is rising)
- `CONGESTION` or `INFRA_FAILURE` — slope biased downward (network is degrading)

**Why not use `forecasting_benign.pkl`:** This pkl model was trained on pcap-derived byte rates (2–5 Mbps per flow). The GNN measures interface counters at full Mininet speed (180–530 Mbps aggregate due to TCP uncapped + both-endpoint counting). Feeding pkl predictions into a GNN-scale chart would produce near-zero predictions next to 400+ Mbps historical values.

## Training the GNN

Training is performed offline in `ml_training/`. See [ml_training/README_GNN.md](../ml_training/README_GNN.md) for the full training and inference command reference.

### Quick reference

```bash
cd ml_training

# Train on 30-second prediction horizon
python train_gnn.py \
    --data_dir data/gnn_datasets/gnn_<timestamp> \
    --horizon horizon_30s \
    --model_type temporal_gat \
    --seq_len 5 \
    --epochs 100 \
    --hidden_dim 128 \
    --use_class_weights

# Batch evaluation
python inference_gnn.py \
    --model_path models/gnn/temporal_gat_horizon_30s_*/checkpoint_best.pt \
    --data_dir data/gnn_datasets/gnn_<timestamp> \
    --mode batch \
    --detailed_report
```

### Deploying a new model

After training, copy the checkpoint and scaler to the Flask backend:

```bash
cp ml_training/models/gnn/<exp>/checkpoint_best.pt \
   mininetDashboard/backend/models/gnn_model_complete.pt

cp ml_training/gnn_scaler.pkl \
   mininetDashboard/backend/models/gnn_scaler.pkl

cp ml_training/label_mapping.json \
   mininetDashboard/backend/models/label_mapping.json
```

Restart the Flask backend. The GNN engine reloads models on startup.
